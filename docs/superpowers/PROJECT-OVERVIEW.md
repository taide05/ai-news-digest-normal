**最后更新:** 2026-06-08
**当前阶段:** v0.1 代码完成，待验收

---

## 一、项目定位

一个本地运行的个人 AI 资讯学习工具。不是资讯推送器，是 **AI 学习导师**——帮用户把表层信息转化为可理解的深度知识。

**用户:** 一个人使用，AI 领域学习者，中文环境，不具备专家级分辨力，需要 AI 辅助理解"这意味着什么"。

---

## 二、终局愿景（v1.0+）

```
用户每天双击快捷方式
  → 自动采集 → 智能聚类 → 企微通知
  → Web 面板阅读 → AI 逐篇深度解读
  → 系统学习用户兴趣 → 个性化推荐
  → 周报/月报总结学习轨迹
```

## 五、开发工作流（从 v0.2 开始启用）

```
每个 task 的执行流程：

  1. 派发实现子代理
       │
       ├── 子代理提问 → 回答 → 继续
       │
       ▼
  2. 子代理: 实现 + 测试 + 自审 + commit
       │
       ▼
  3. 派发 spec 合规审查子代理
       │
       ├── ❌ 不合规 → 实现子代理修复 → 重新审查
       │
       ▼
  4. 派发代码质量审查子代理
       │
       ├── ❌ 有问题 → 实现子代理修复 → 重新审查
       │
       ▼
  5. ✅ Task 完成 → 下一个 task
```

### 审查视角

每个 task 从以下视角审视：

| 视角 | 关注点 | 谁负责 |
|------|--------|--------|
| **架构师** | 模块边界清晰、接口设计合理、技术选型正确、扩展性 | spec 合规审查 |
| **工程师** | 代码质量、错误处理、边界条件、测试覆盖、性能 | 代码质量审查 |
| **PM** | 范围控制、优先级、里程碑、风险、依赖 | 主会话协调 |
| **QA** | 测试策略、验收标准、回归风险 | 代码质量审查 |
| **安全** | 数据保护、输入验证、最小权限 | 代码质量审查 |

### 阶段 D: v0.2 开发

**目标:** 按 C 阶段产出的 plan，用 subagent-driven 模式逐个 task 实现

```
每个 task:
  实现子代理 → spec 审查 → 代码质量审查 → ✅ → 下一个
```

**工作原则:**
- 子代理负责所有编码工作
- 每个 task 必须通过两道审查才能标记完成
- 主会话负责协调、回答子代理问题、跟踪进度
- 持续执行，不中断（除非遇到阻塞）

### 阶段 T: v0.2 系统测试

**目标:** 开发的子代理写的是单元测试，阶段 T 做系统性质量把关——跑全量、查遗漏、探边界。

| # | 行动 | 执行方式 | 说明 |
|---|------|---------|------|
| T1 | 全量测试运行 | 子代理 | `pytest tests/ -q --tb=short`，确认全部通过 |
| T2 | 回归检查 | 子代理 | 对比上一版本的测试数量，确认只增不减 |
| T3 | 边界条件测试 | 子代理 | 空输入、超长输入、并发请求、网络超时、DB 锁定 |
| T4 | 集成烟雾测试 | 子代理 | 启动服务器 → 访问各页面 → 检查 HTTP 状态码 |
| T5 | 性能检查 | 子代理 | N+1 查询、大循环、未关闭的 HTTP client、多余 commit |
| T6 | 安全回归 | 子代理 | XSS、SQL 注入、SSRF、密钥泄露——快速扫描新代码 |
| T7 | 缺失测试补充 | 子代理 | 发现未覆盖的路径 → 直接写测试补上 |
| T8 | 问题修复 | 子代理 | T1-T7 发现的问题逐项修复 |

**门禁:** 阶段 T 必须全部通过才能进入阶段 E。任何测试失败 = 回到阶段 D 修复。
